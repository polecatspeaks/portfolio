# Friction log (template)

Raw material for the session-start tooling retro. Friction is logged **as it happens**, not
reconstructed later - **a retro that runs on memory is a memory test**, and in a shop where
the workforce evaporates nightly, memory is the one thing guaranteed absent.

Log anything that cost time, produced a wrong diagnosis, or made a defect possible: a tool
that lied, a default that bit, a missing capability, a command retried, a manual step that
should be mechanical. Small entries are fine - the point is the pattern across many, not the
severity of any one.

Format: `date | what happened | what it cost | class`.

## Things worth logging that people usually do not

- **Retro false positives.** When the retro itself misclassifies something, keep the entry
  with the correction visible. An instrument that hides its own misfires cannot be calibrated.
- **Your own process violations**, named precisely. Blameless means the record gets *sharper*,
  not vaguer.
- **Questions that turned out to be already answered** in a setup doc or a parked trigger -
  that is the prior-art class, and it is the cheapest one to fix.
